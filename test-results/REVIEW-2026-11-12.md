# Playwright review and feature opportunities

November 12, 2026, America/New_York.

**25/31 browser scenarios passed. Six extended assertions found application defects. All 19 existing scenarios and all 11 offline regression tests passed.** No displayed Python exceptions or uncaught browser JavaScript errors were recorded in the final scenario results. Application source was unchanged; this review adds test coverage and documentation.

The tests used Python Playwright 1.60.0 with installed headless Google Chrome against a fresh Streamlit server at `http://127.0.0.1:8503`. Browser tests used live Yahoo Finance responses, separate browser contexts, a 1440 × 1000 desktop viewport, and the existing 390 × 844 mobile check. Default historical dates were January 1, 2022 through January 1, 2025, with an exclusive end date. “Live” describes the data provider connection, not a current-date analysis period.

## Confirmed findings

| Priority | Finding and reproduction | Cause and suggested correction |
| --- | --- | --- |
| High | **Portfolio A and B can compare different periods.** Keep Portfolio A at its defaults and enter `ARM` for B. A begins January 4, 2022; B begins September 15, 2023. Both end December 31, 2024. Their total returns therefore cover different holding periods. | `calculate_portfolio_comparison` calculates each portfolio independently. Intersect usable price dates before calculating either return series, use the same initial valuation date, and disclose the effective period. Recompute the chart and comparison table from that common window. |
| High | **The SPY benchmark can cover a much longer period than the portfolio.** Add `ARM` to the default portfolio. The portfolio growth trace starts September 15, 2023, while SPY starts January 3, 2022. The displayed return and outperformance calculations inherit the mismatch. | The portfolio loader drops observations before every holding has data; `calculate_portfolio_growth` independently normalizes the full SPY series. Align portfolio and benchmark prices before computing and normalizing their growth. Include an initial valuation point for both. |
| Medium | **The same portfolio has two Sharpe ratios.** The default headline shows **1.04**, while Portfolio A's comparison table sends **1.1373036465** to the browser. | `risk_metrics.py` subtracts a 2% annual risk-free rate; `calculate_portfolio_comparison` subtracts none. Use a shared calculation and disclose or expose the risk-free assumption. |
| Medium | **Diversification counts unfunded holdings.** Set all sliders to zero, then MSFT to 1.0. The allocation is 100% MSFT, but the health insights still say “Good diversification.” | `calculate_health_score` uses `len(weights)` including zero weights, inflating the diversification component. Count positive allocations and consider an allocation-based concentration measure. |
| Medium | **The concentration recommendation names the wrong sector.** Set XOM to 100% and every other holding to zero. “Largest Sector” correctly shows Energy, while Recommendations says “Technology concentration is high.” | The recommendation in `dashboard.py` hardcodes Technology. Use the actual largest sector name. |
| Low | **Health insights repeat under each recommendation.** Move AAPL's slider to its maximum. The same three health insight cards appear multiple times. | The health-insights loop is nested inside the recommendations loop. Render each list once. The related Strengths section is visibly empty; its heading has no content before the divider. |

The six failed browser assertions correspond to the six rows above. The empty Strengths section is an additional visual/source observation, not a separately counted automated scenario.

## Features worth adding

These are product suggestions based on this app's current UI and source, not implemented changes.

| Suggested order | Feature | Concrete scope and benefit | Relative effort |
| --- | --- | --- | --- |
| 1 | **Flexible dates and visible data coverage** | Replace fixed 2022–2025 year choices with date inputs and presets such as 1Y, 3Y, 5Y, and YTD. Show requested versus effective dates, source, last fetch time, and an explicit refresh action. Explain shortened coverage when a holding listed later. | Small–medium |
| 2 | **Save and reload named portfolios** | Preserve ticker weights and analysis settings in downloadable/uploadable JSON snapshots. Add validated CSV import for holdings and allocations. Users can reuse work across new browser sessions and compare saved allocations. | Medium |
| 3 | **Adjustable Portfolio B and benchmark selection** | Give B its own allocation controls, an equal-weight action, and a copy-from-A action. Offer benchmark selection with clearly stated data coverage. This supports controlled allocation experiments. | Medium |
| 4 | **Rebalancing and contribution analysis** | Let users choose buy-and-hold versus monthly/quarterly rebalancing and include transaction-cost assumptions. Show each holding's return and risk contribution and trades needed to return to target weights. The current weighted daily-return calculation implicitly maintains constant weights each day. | Medium–large |
| 5 | **Drawdown and scenario views** | Add an underwater chart with drawdown dates and recovery duration, then optional user-defined market/sector shocks with estimated dollar impacts from a starting portfolio value. Keep historical results and hypothetical scenarios clearly labeled. | Medium–large |
| 6 | **Exportable analysis snapshot** | Produce a report containing settings, effective dates, assumptions, metrics, charts, and recommendations. The existing dataframe toolbar already offers CSV export; a full analysis report would add context and reproducibility. | Medium |

Fix the period alignment, Sharpe consistency, and misleading health messages before building more advanced analytics. Flexible dates and saved portfolios are the strongest next feature candidates because they remove immediate limits visible in the current app.
